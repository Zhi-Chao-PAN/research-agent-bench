# From research method to a bounded agent task

This is an AI-assisted method-to-implementation index for reviewers. It maps English source papers to the actual code and names the points where this project **changes** the original setup. It does not prove that the applicant has personally read the papers or can explain them without help.

| Source method | Implemented task and code pointer | Difference that matters |
|---|---|---|
| [Cormack, Clarke & Büttcher, SIGIR 2009, RRF](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf) combines ranked lists with `sum_i 1/(k + rank_i(d))`; its validation held `k=60` after a pilot. | [`evaluator/core.py`](evaluator/core.py) fuses frozen BM25 and TF-IDF ranks as `w/(k+r_BM25) + (1-w)/(k+r_TFIDF)`. [`validate`](evaluator/core.py) confines `k` to integer 1–200 and `w` to finite 0–1. | **Weighted two-ranker tuning on NFCorpus is our task construction, not a reproduction of the original paper's TREC/LETOR results or its unweighted fixed-`k` validation.** |
| [Thakur et al., BEIR](https://arxiv.org/abs/2104.08663) studies heterogeneous retrieval datasets and emphasizes comparing robust baselines. | [`prepare_nfcorpus.py`](prepare_nfcorpus.py) and [`evaluator/build_cache.py`](evaluator/build_cache.py) construct a single NFCorpus rank-cache task; [`evaluator/core.py`](evaluator/core.py) scores exponential-gain nDCG@10. | One NFCorpus split and two lexical rankings cannot establish cross-dataset zero-shot generalization. Our nDCG gain convention is explicit and must not be silently equated with a differently configured leaderboard. |
| A research-agent optimization loop needs a measurable edit and feedback boundary. This is our engineering protocol, **not a claim from the two papers above**. | [`create_dev_task.py`](create_dev_task.py) creates a development-only task. Its [`supervisor.py` template](fresh-repeat-v5/fresh-dev-agent-01/supervisor.py) freezes input hashes, records a hypothesis before each trial, rejects duplicates and a seventh call, and returns development metrics. [`verify_public_traces.py`](verify_public_traces.py) audits archived selection. | The directory and supervisor are a task protocol, not an operating-system sandbox. Public NFCorpus test labels are not secret; only the workflow withholds them during six-call selection. |

The agent can change exactly two numbers, `k` and the BM25 weight. Feedback is deterministic for a frozen rank cache, cheap enough for repeated CPU trials, and expressed as a single development nDCG@10 objective plus diagnostics. That makes this a tractable *bounded* agent task: an evaluator can reject invalid edits, show feedback within a fixed budget, and compare the final choice with equally budgeted preset or random search. The search baseline is necessary because an agent that only beats its first guess has not shown useful optimization.

The observed result is negative. The three new LLM trajectories each used six calls but chose one identical configuration and one unique public-test ranking, scoring 0.307044 versus 0.307294 for the preset six-point search. The public test landscape was inspected during the wider exploratory work. The project therefore demonstrates a runnable task and an honest failure analysis, not agent superiority, a blind benchmark, or a replication of either source paper.

Why this task was prioritized over turning the separate [LoRA reproduction](https://github.com/Zhi-Chao-PAN/lora-robustness-reproduction/blob/reviewer-snapshot-2026-09-23/METHOD_NOTE_EN.md) into a six-call agent problem: changing LoRA rank or training settings requires model downloads, GPU time and input-provenance checks before a score can be trusted. The separate study is useful for method reproduction and robustness analysis, but this CPU rank-fusion task has a smaller edit space and faster, more inspectable feedback. This is an engineering suitability judgment; it does not come from the RRF, BEIR or LoRA authors.

To inspect the design without third-party data, run `python3 verify_public_traces.py`, then (after installing NumPy 2.2.6) `python synthetic_demo.py`. The latter uses fabricated data and tests the supervisor budget gate; the real NFCorpus numerical rebuild is documented in [REPRODUCTION_QA.md](REPRODUCTION_QA.md). Neither quick check establishes an applicant's independent ability. A reviewer can ask the applicant to explain the formula, point to the code, identify the original-paper deviation, and run a fresh task under observation.
